# Algorithm Naming Audit

Audit date: 2026-08-22  
Evidence SHA: `b56cc60913eadae19c8e8f9aac529c2cb03179d0`  
Scope: analytical functions, configuration, result fields, CLI/report language, and validation names.

The audit compares observable implementation with the ordinary technical meaning
of each term. “Mismatch” means the current name must change or the implementation
must be replaced. It does not mean the underlying heuristic is necessarily
useless.

## Phase 3 decisions implied by the audit

1. Follow the plan’s default remediation path: preserve the existing heuristic
   calculations but rename them to multiscale residual/scale-energy terms.
2. Rename the DoG radius helper; do not implement Gaussian convolution solely to
   preserve a decorative name.
3. Rename the raster spectral diagnostic and correct its radial shell aggregation.
4. Make the marked engine’s interpretation neutral; keep MMR language only in an
   explicitly MMR-facing report policy.
5. Treat the additional pair-correlation, beta-binomial, equivalence, difference,
   and validation mismatches as audit-discovered findings. Add them to the findings
   matrix rather than silently folding them into unrelated IDs.

## Reference policy

Established names are retained only when implementation tests establish the
defining operation. External references above define terminology; repository
fixtures and differential tests establish that Marklab actually performs it.
