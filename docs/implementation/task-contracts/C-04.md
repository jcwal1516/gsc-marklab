## Canonical domain contract

### Complete expected-cell table with explicit vector validity

- `CellEmbeddingTable` owns a positive dimension, strictly increasing unique `CellId`s, one row-major contiguous `Vec<f32>` of exactly `rows × dimension` storage, and one validity/missing-status entry per expected cell.
- Construction checks every integer conversion and multiplication before allocation or indexing. A caller supplies an explicit retained-byte limit; no ambient-memory default silently admits a multi-gigabyte table.
- Every present component must be finite. Negative zero is canonicalized to positive zero at the constructor/import boundary. No implicit `f64`, `f16`, integer, binary-blob, variable-list, transpose, or dimension cast is accepted.
- Every expected cell has one row. `EmbeddingStatus` is the closed C-04 extraction-validity vocabulary with exact wire strings `present`, `missing_vector`, `extraction_failed`, and `qc_rejected`; unknown missingness is rejected. A present row exposes exactly one vector. A non-present row exposes no vector.
- Internal storage for a non-present row is a private canonical positive-zero-bit slot solely to preserve checked contiguous addressing. The physical embedding column is non-null in both formats; construction, writing, and decoding require every component of a non-present row to have bits `0x00000000`, and nonzero or negative-zero hidden data is rejected. `EmbeddingStatus` is the sole explicit validity owner. The slot is never returned as a vector, never treated as observed data, and contributes no component bits to logical identity. A genuine all-zero present vector remains valid and distinct from missing because its status is `present`.
- Zero rows are structurally representable for format oracles, but the CellViT source-bundle importer requires a non-empty explicit expected cell set. An absent expected row, extra row, or duplicate row is an error rather than a missing-vector representation.
- Row and block access returns validity plus borrowed present slices; it cannot expose missing fillers. Statistical accumulation is `f64`; C-04 itself computes only integrity/QC checksums and no scientific estimand. C-06 still owns measured-versus-predicted and general mark status, which this extraction-validity enum does not encode.
- `EmbeddingQcSummary` has exactly checked `u64` fields `row_count`, `present_count`, `missing_vector_count`, `extraction_failed_count`, `qc_rejected_count`, and `all_zero_present_count`, one `u32 dimension`, and the logical digest. It is accumulated once in ascending `CellId` order, and the four status counts must sum to `row_count`. It carries no phenotype threshold, scanner/site analysis, cohort effect, prediction, or technical-confounder conclusion; those WS-24 obligations remain open.
- `CellEmbeddingArtifact` binds the embedding record, row-link record, provenance record, exact shape/dtype, logical digest, and QC summary. This compact project metadata may be referenced by future schemas; the matrix and per-row vectors never enter result JSON.

### Cell-row link

- `CellEmbeddingRowLink` is a separate immutable table keyed by `CellId` with non-null `u64 source_cell_row` and nullable `u64 source_embedding_row`.
- The link binds exact source-cell, source-vector, expected-cell-set, identity-map, and converter/importer artifact IDs, expected row count, and an ordered linkage digest.
- Validation requires an exact bijection over the declared expected cell set, unique gap-free source cell rows, unique gap-free referenced embedding rows, in-range indices, and membership as `HierarchyKind::Cell` in the supplied hierarchy. `present` and `qc_rejected` require `source_embedding_row`; `missing_vector` and `extraction_failed` require it to be absent. A source cell absent from the identity map or expected set is an error, not a missing status.
- Neither position, filename, coordinates, contour, slide text, specimen text, nor same-length arrays can create a link. A source-specific adapter may accept a documented explicit `embedding_row`, but it must verify the entire mapping before reading values.
- The observed `cellvit_he_bundle` 1.0 adapter produces `present` for every accepted row because its frozen profile requires one finite NPY vector and source `qc_pass` exactly `True` for every CSV row. It never converts malformed/absent source values into a missing status. The other statuses are available to explicit, provenance-bearing converters and constructors.

### Logical digest

- Every digest in this section is `ContentDigest::from_framed`: the domain and every following field receive their own unsigned 128-bit big-endian byte-length prefix. Artifact IDs and digests contribute their raw 32 bytes, never hexadecimal text. Integers contribute fixed-width big-endian bytes.
- The row-link digest domain is `marklab-cell-embedding-row-link-v1`, followed by raw source-cell, source-vector, expected-cell-set, identity-map, and converter artifact IDs; `u64` row count; then for each ascending `CellId`: its UTF-8 bytes, `u64 source_cell_row`, the exact marker `embedding-row-present` plus a `u64` row or the exact marker `embedding-row-absent`.
- `CellEmbeddingLogicalDigest` uses domain `marklab-cell-embedding-logical-v1`, followed by raw provenance artifact ID, row-link digest, expected-cell-set artifact ID, `u32` dimension, `u64` row count, then for each row canonical `CellId` UTF-8, the exact status wire string, and one four-byte big-endian `f32::to_bits` field per present component. There is no separate free-text reason field.
- The logical digest is independent of Arrow versus Parquet, validity-buffer layout, private missing fillers, record-batch/row-group boundaries, and compression. It changes with any cell, status, present value, dimension, provenance, or row-link change.
- Encoded `ArtifactId` remains C-03 content/schema identity. Different valid physical encodings may have different artifact IDs while sharing one logical digest. Only a pinned writer configuration may claim a deterministic byte digest.
- A tiny obviously correct reference implementation differentially checks the chunked digest implementation, including signed zero, empty, singleton, boundary-sized chunks, and malformed length cases. Fixed golden vectors cover expected-set, identity-map, row-link, canonical provenance JSON/digest, logical table digest, and one encoded Arrow and Parquet artifact.

### NPY/CSV parsing

- Accept only bounded NPY v1.0 or v2.0 with exact magic/version/header length, ASCII header bytes, a final newline, specification-compatible 16-byte total-header alignment, a two-dimensional shape, C order, exact descriptor `'<f4'`, positive width, checked payload length, and no trailing bytes. - Parse the NPY header with a small closed grammar: single-quoted keys/value, exact `False`, a two-element tuple of canonical unsigned decimal integers, ASCII space/tab/carriage-return/form-feed/vertical-tab as internal whitespace, optional trailing commas in the shape tuple and dictionary, and no comments/escapes/evaluation. Only ASCII spaces may pad the closed dictionary before its one final newline. Validate file length and every multiplication before allocating. Do not evaluate Python syntax, import NumPy/Python, or accept pickled object arrays.

The logical-record metric is raw encoded bytes excluding the terminating CR/LF bytes and including quotes and doubled quotes. Every field is nonempty. The seven identifier/label fields are control-free UTF-8 of at most 128 bytes; `block_500_id` is control-free UTF-8 of at most 32 bytes; `split` is a 1–32 byte ASCII token `[A-Za-z0-9._-]+`. `native_row`, `embedding_row`, and `cell_type_id` are canonical unsigned decimal within `u64`, `u64`, and `u32`. ## Physical Arrow IPC and Parquet contract

### Exact tables

- Embedding schema `marklab.cell_embedding_table` version 1 has exactly three non-null columns: `cell_id: Utf8` primary key; `embedding: FixedSizeList<F32, declared_dimension>` with a non-null child; and `embedding_status: Utf8` using the closed extraction-validity vocabulary. `present` permits any finite canonical vector; every other status requires all positive-zero component bits.
- Row-link schema `marklab.cell_embedding_row_link` version 1 has exactly non-null `cell_id: Utf8`, non-null `source_cell_row: U64`, and nullable `source_embedding_row: U64`, with `cell_id` as primary key. `source_embedding_row` follows the exact status rules above.
- Embedding-table metadata contains exactly the seven bounded keys `marklab.schema_id`, `marklab.schema_version`, `marklab.encoding_version`, `marklab.expected_cells_artifact_id`, `marklab.provenance_artifact_id`, `marklab.row_link_artifact_id`, and `marklab.logical_digest`. Row-link metadata contains exactly `marklab.schema_id`, `marklab.schema_version`, `marklab.encoding_version`, `marklab.expected_cells_artifact_id`, `marklab.identity_map_artifact_id`, `marklab.source_cells_artifact_id`, `marklab.source_vectors_artifact_id`, `marklab.converter_artifact_id`, and `marklab.row_link_digest`. Values must equal the record, manifest, direct dependencies, and decoded logical content; unknown metadata is rejected.
- Arrow accepts a random-access IPC file only; IPC streams and dictionaries are rejected. The corresponding sorted metadata keys live in Arrow schema metadata and Arrow file custom metadata is empty.
- Parquet has no fixed-size-list physical primitive. Its exact accepted embedding schema is root `marklab_cell_embedding_table`: required UTF-8-annotated `BYTE_ARRAY cell_id`; required standard three-level `LIST embedding` containing repeated group `list` with required `FLOAT element`; and required UTF-8-annotated `BYTE_ARRAY embedding_status`. Every list has exactly the dimension from the required C-03 `TableManifest`, including positive-zero fillers for non-present rows. The row-link root is `marklab_cell_embedding_row_link` with required UTF-8 `BYTE_ARRAY cell_id`, required unsigned-annotated `INT64 source_cell_row`, and optional unsigned-annotated `INT64 source_embedding_row`. Parquet key-value metadata contains exactly the corresponding application keys. `ARROW:schema` is absent and rejected; an expected Arrow schema is supplied only after independent physical validation.

### Verified-reader boundary

- Add the named public supertrait `ArtifactReadSeek: Read + Seek + Send` with a blanket implementation, because a multi-non-auto-trait object is not legal. `LocalArtifactStore::with_verified_reader` opens the record's digest-derived managed regular file capability-relative and read-only, verifies digest/length on the retained descriptor, seeks it to the start, invokes a scoped caller closure through `&mut dyn ArtifactReadSeek` while retaining the shared cooperative lock, then seeks and verifies that same descriptor again.
- The callback has a generic typed error separated from store-integrity errors. Post-read verification runs even after callback failure; a post-read integrity error takes precedence, otherwise the callback error is returned. Integrity failure is never a cache miss.
- The API exposes no ambient path, root capability, owned clone, or locator key. It protects against path replacement and cooperative writers under C-03's trusted-root model; it does not sandbox trusted Rust callback code or a hostile administrator that bypasses the API.
- Add `LocalArtifactStore::publish_send`, whose callback receives `&mut (dyn Write + Send)`, while preserving existing `publish` unchanged. Both delegate to the same publication implementation and have identical digest, durability, idempotency, cleanup, and injected-fault tests. This is required because Parquet `ArrowWriter<W>` requires `W: Write + Send`.

### Bounded preflight and decode

- No Arrow-rs high-level reader sees bytes until a raw preflight has enforced file bytes, trailer/footer/header bytes, nesting/tables/fields, metadata entries/bytes, row groups/record batches, column chunks, pages, rows/values, dimension, batch rows, every checked file range, and retained/decoded-byte budgets.
- Arrow preflight reads magic/trailer/footer length first, then verifies the Footer FlatBuffer with explicit maximum depth/table counts. It rejects dictionary blocks and checks every record-batch block's nonnegative offset, metadata length, body length, alignment, checked end, file range, batch count, and aggregate bytes. Before `FileReaderBuilder::build`, it reads each bounded metadata section, verifies its Message FlatBuffer with `root_as_message_with_opts`, requires a RecordBatch header, bounds nodes/buffers/variadic counts, and validates every buffer offset/length against the body and decoded budget. It checks the shallow exact schema/metadata, never uses `with_skip_validation`, and calls `validate_full` on every top-level and nested returned array.
- Parquet preflight implements a budgeted compact-Thrift input protocol before any stock metadata or page decoder. It bounds nesting, fields, lists/maps, strings/bytes, schemas, metadata entries, row groups, column chunks, page headers, compressed/uncompressed page bytes, values, and total decoded bytes. It parses every footer and page header, validates exact schema/offset/range/order/count/encoding declarations, and admits only the canonical uncompressed profile before the same bytes reach Arrow-rs. Fuzz regressions include malicious giant list/string/page declarations that are rejected before stock decode or large reserve.
- Within the verified callback, a mutex-backed borrowed `ChunkReader` supports bounded metadata/range reads without an owned escaping handle. After preflight, copy at most one validated row group into owned `bytes::Bytes`, decode it through a custom `RowGroups` implementation and `ParquetRecordBatchReader::try_new_with_row_groups`, validate batches, then drop those buffers before the next row group. This is O(row-group × dimension), not whole-file buffering.
- Fully validate exact type/nullability/child type, hidden non-present positive-zero fillers, row order, status/value consistency, finiteness, total rows, dimension, metadata IDs, logical digest, and QC summary. External Arrow/Parquet/CSV errors map to bounded typed codes and offsets/counts only; raw third-party error strings/metadata are never surfaced. Secret-sentinel tests cover syntax, schema, metadata, value, store, and post-verification failures.

### Canonical writers

- Exact Arrow profile v1: Arrow/IPC 56.2.1; IPC metadata V5; 64-byte alignment; non-legacy format; no compression/dictionaries; fixed 8,192-row record batches; lexicographically sorted exact schema metadata; empty file custom metadata; one final file footer.
- Arrow profile v1 further fixes the `FixedSizeList` child as non-null `item: Float32` with no field metadata, the all-ones validity buffers including unused tail bits emitted for non-null arrays by the canonical 56.2.1 builders, and the exact status-derived validity bitmap for nullable `source_embedding_row`. Reader acceptance is the exact bounded structural profile, not a claim that every accepted FlatBuffer byte is a canonical-writer replay: 58 zero header-padding bytes, one initial V5 schema message, sorted exact Schema custom metadata, contiguous 64-byte-aligned schema/batch metadata and bodies without gaps, one exact EOS marker, and one footer. Footer verification uses maximum depth 8, 32 tables, and 1-MiB apparent size. The separately parsed initial message must be V5 Schema with zero body, no Message custom metadata, and a schema exactly equal to the footer under maximum depth 8, 32 tables, and 64-KiB apparent size. Record-batch message verification uses maximum depth 4, 4 tables, and 64-KiB apparent size.
- Exact Parquet profile v1: Parquet 56.2.1; `PARQUET_2_0`/data page V2; `UNCOMPRESSED`; dictionary, bloom filters, statistics, column/offset/page indexes, and Arrow-schema metadata disabled; `PLAIN` value encoding with only required RLE definition/repetition levels and exact footer encoding declarations pinned by the golden; 8,192-row row groups and public Arrow input batches; internal Parquet `write_batch_size = 1,024`; 1,024-row page property; 1-MiB page-byte property; exact root name; exact `created_by = marklab-embeddings/0.1.0 parquet-56.2.1 profile-v1`; and exact application key-value entries in lexicographic key order. `ArrowWriterOptions::with_skip_arrow_metadata(true)` is mandatory.
- In Parquet 56.2.1, canonical leaf footer declarations are exactly `[PLAIN, RLE]` even for required flat columns; pages still use PLAIN values, and level payloads are empty unless the schema requires them. Public Arrow input batches and row groups are at most 8,192 rows, while `write_batch_size = 1,024` makes the 1,024-row page property effective at every internal boundary. The page-row and 1-MiB page-byte values are pinned writer properties, not claimed hard emitted ceilings; preflight independently enforces hard page budgets. Exact page-encoding statistics, one type-order entry per leaf, and compatible dual logical/converted annotations are required canonical footer metadata rather than forbidden value statistics or indexes.
- A writer first computes the expected encoded digest/length through a deterministic counting/hash sink, then replays the same bounded batches through the store without retaining the whole file. Already located truthful records use `LocalArtifactStore::publish_send`; fresh canonical output uses the separate draft publication path. The store catches nondeterminism in both paths.
- The fresh store-owned draft is not an `ArtifactRecord`, cannot serialize or enter a catalog, and constructs the truthful managed locator only after successful durable publication. It reuses C-03 publication, verifies exact digest/length, preserves idempotency and failure cleanup, and returns no record on callback or integrity failure; callers never create a placeholder external locator. A row-link physical file is validated against the supplied logical row link or jointly with the embedding table and is never decoded alone into a status-bearing domain link.
- Golden fixtures pin one exact Arrow and Parquet SHA-256. Tests write twice in-process and invoke the same integration-test writer in two fresh child processes, requiring identical bytes and the golden. The byte-determinism claim is limited to exact profile v1, pinned dependencies, and admitted targets; logical identity remains format/chunk independent.
- Arrow/Parquet and every allowed batch/row-group partition must yield identical canonical rows, logical digest, and QC summary. Encoded bytes are not claimed equal across formats.

## Mapping and chunk semantics

- Marklab provides a borrowed-contiguous-byte parser and a bounded verified `Read + Seek` parser with exact parity. The borrowed-byte API is compatible with bytes supplied by an externally established immutable mapping but does not create an OS mapping or call itself memory-mapped.
- OS mmap has been evaluated and is explicitly deferred: C-04 has no safe portable mapping owner, Marklab forbids unsafe code, and the master plan makes mapping optional/evaluated separately. Borrowed-contiguous/chunk parity closes C-04's safe-path requirement; no mmap or zero-copy claim is made. A later accepted dependency/portability decision may reopen actual mapping without changing logical identity.
