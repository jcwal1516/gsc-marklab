## Estimand, availability, and arithmetic

For present embedding rows `I`, `n = |I|`, declared probability `p_i`, component `x_ij`, and positive dimension `D`:

```text
p_mean = sum_i(p_i) / n
x_mean[j] = sum_i(x_ij) / n
cov[j] = sum_i((p_i - p_mean) * (x_ij - x_mean[j])) / n
energy = sum_j(cov[j] * cov[j]) / D
```

- Use the population denominator `n`, not `n - 1`.
- Promote stored `f32` values to `f64`. First accumulate embedding sums in row/component order and divide in component order; then accumulate centered cross-products in the same stored order; finally divide, square, and sequentially sum components before one division by `D`.
- `Available` carries `Some(energy)` when at least two present rows have nonconstant numeric probabilities.
- `InsufficientPresentRows` carries `None` for fewer than two present embeddings. `NoProbabilityVariation` carries `None` when at least two present rows have equal probabilities. Both retain the present probability mean when defined, and neither allocates accumulators or performs component arithmetic after the already-enforced conservative caps.
- Canonicalize signed zero in the numeric result. Promise repeat determinism only; do not claim bitwise row/component permutation or rotation invariance.

Runtime is `O(N*D)` for available inputs plus `O(N)` binding/probability work. Incremental arithmetic storage is exactly two `D`-component `f64` accumulators; retained result state is bounded metadata, QC, counts, and scalars only.
