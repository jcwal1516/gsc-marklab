## Patch context and support

`PatchEmbeddingContext` version one freezes one slide and one extraction scale:

- exact source X/Y image-pixel and target X/Y physical-micrometre frame IDs plus their by-value 2-D definitions;
- exact pixel convention and a named transform whose source/target equal those frames, whose uncertainty is absent, whose off-diagonal bits are positive zero, whose positive diagonal bits exactly equal the reduced MPP values converted to `f64`, and whose finite translation bits are preserved after signed-zero canonicalization;
- reduced positive X/Y micrometres-per-pixel;
- positive source-image width/height;
- positive patch width/height;
- explicit stride and overlap with checked `stride + overlap = patch` per axis;
- one closed effective receptive field: `full_input`, or a positive reduced-rational X/Y rectangle no larger than the input patch and centered exactly at the patch center (offsets are the exact rational half-differences); receptive-field units are input pixels;
- one exact `PatchBoundaryPolicy`; and
- half-open image support `[x, x + width) × [y, y + height)`.

One table/context represents one scale. Multiscale use is multiple explicitly linked artifacts, never mixed scale rows.

`PatchFootprint` carries a typed `PatchId` and `i64` pixel origin; context width/height are converted to `i64` and added with checked arithmetic. Source image support is exactly `[0, width) × [0, height)`. `FullyContainedOnly` requires nonnegative origins and endpoints within source support. `Reflect` and `ConstantRgb` allow out-of-bounds extent only when the half-open patch has positive-area intersection with source support and the out-of-bounds distance on each side is strictly less than the corresponding patch extent; an all-padding/all-reflection patch is rejected. Boundary contact without positive area is not intersection.

`PatchFootprintSet` is the single spatial-support owner for each expected patch: it matches the expected patch set exactly, validates hierarchy ownership, patch extent/context consistency, boundary policy, and a domain-separated logical digest. Footprints are not repeated in cell links or matrix rows. The set is sampled-patch support metadata; its union is not relabeled a full tissue or inferential observation window.

Extraction-grid overlap/stride and actual overlap among distinct sampled footprints are separate concepts. `PatchOverlapGraph` is derived deterministically from one exact footprint set using positive-area half-open rectangle intersection and stores each overlapping unordered pair once with `left_patch_id < right_patch_id`. Every expected patch belongs to one deterministically derived connected component, including isolated patches; the component identity is the minimum `PatchId` in that component and is never assigned from traversal order.

Because one context fixes every footprint extent, bucket width/height are exactly the patch width/height converted to positive `i64`. A patch origin maps to `(x.div_euclid(width), y.div_euclid(height))`. Expected patches are visited in increasing `PatchId` order; for each patch, previously inserted patches are examined in the nine buckets `(dy,dx)` with `dy = -1..=1` outer and `dx = -1..=1` inner. Each candidate therefore occurs once against the current patch; exact positive-area intersection decides admission, and the stored pair is sorted by ID. Final edges are lexicographically sorted.

The indexed implementation must differentially match a brute-force oracle and remain O(p log p + e) time / O(p + e) retained memory for p patches and e overlaps. Construction uses two identical passes: count/check buckets, edges, and union-find/component storage without retaining candidates, then allocate exact capacities and reproduce counts while materializing. It may not retain an uncharged candidate-pair list. No table-wide overlap scalar may substitute for the graph on irregular samples.

## `CellPatchLink` semantics

`CellPatchLink` is an immutable grouped assignment plus edge table. Its only vector reference is `PatchId`; it owns no vector components. It binds an exact C-04 `ExpectedCellSet` artifact and has exactly one canonical group/anchor for every selected cell. Edges are canonical by `(CellId, PatchId)`, duplicate pairs are rejected, and any number of cells may reference one patch.

Every link binds exact expected-cell, expected-patch, patch-footprint, patch-context, and producer/converter artifact identities and logical digests. It does not bind model-specific patch-vector bytes. Each grouped cell records one finite anchor coordinate in the exact image frame. Containment means anchor containment only, never whole-cell or contour containment.

Version one has two table-wide modes:

1. `contained_shared`: weight is absent. The canonical edges must equal all patch footprints whose half-open windows contain each supplied anchor. A group with no containing footprint is retained once as `outside_sampled_support` with zero edges. Overlapping memberships are preserved rather than reduced to an implicit primary patch.
2. `declared_weighted_interpolation`: an `assigned` cell has one to four distinct patch edges with positive integer numerators over one positive group denominator; numerators sum exactly to the denominator and the gcd of all numerators plus the denominator is one. A cell with no declared contributors is retained once as `interpolation_unavailable` with zero edges. The table binds an explicit interpolation producer artifact. C-05 validates the canonical group fraction, identity, frame, and arithmetic; it does not invent or infer the interpolation algorithm.

`assigned`, `outside_sampled_support`, and `interpolation_unavailable` are the complete group-status vocabulary. Mode/status combinations outside the two rules above are rejected. All-containing construction uses two passes: count and budget every group/edge/ID/sort category without retaining candidate edges, then allocate exactly and reproduce the same counts while materializing.

Mixed modes, missing overlap/stride/context metadata, duplicate edges, wrong frames/slides, nonfinite anchors, zero/non-common-denominator/group-noncanonical/non-normalized weights, more than four interpolation contributors, and any vector embedded in a link are rejected. Individual numerator/denominator pairs need not be reduced. Errors expose bounded row/count/category context, never IDs, coordinates, paths, or source values.

## `PatchRegionLink` semantics and geometry boundary

`PatchRegionLink` is canonical by `(PatchId, RegionId)` and binds exact expected patch/region sets, owning slide, patch context/footprints, one exact converter record, and the exhaustive-assessment artifact. It does not bind model-specific patch-vector bytes.

Version one requires `expected_cartesian_exhaustive` assessment policy. The reviewed producer asserts that every checked product pair in `expected_patches × expected_regions` was assessed; `assessed_pair_count` is the exact checked product encoded in the logical identity. Only nonzero declarations are stored, so an absent pair means producer-declared zero overlap, never “not assessed.” Construction consumes one complete declared assessment and derives the sparse link; callers cannot separately provide a link that omits an assessment row. A verified exhaustive-link receipt is required by derived-region provenance. C-05 validates completeness arithmetic and sparse equality to the supplied declaration, not geometric truth.

Version one relations are:

- `fully_contained`, meaning the patch footprint is producer-declared contained by the region and requiring exact fraction `1/1`; and
- `partial_overlap`, requiring a reduced exact rational strictly between zero and one.

The fraction is always producer-declared `area(patch footprint ∩ region support) / area(patch footprint)`. It is never region-area coverage, and fractions for one patch need not sum to one because declared regions may overlap or leave gaps. Region `weighted_mean` visits source patches in increasing `PatchId`, excludes non-present rows, converts each declared fraction and `f32` component to `f64`, accumulates weight and per-component weighted sums sequentially, divides each sum by the positive total weight, casts once to `f32`, and canonicalizes signed zero. With no present positive-weight source, the derived row is `MissingVector`. Slide `arithmetic_mean` follows the same fixed ID/component order with unit weights and one final `f64` division/cast; no present source likewise yields `MissingVector`. Output dimension must equal the source table.

Finalization clarification accepted 2026-08-23 under DEC-0036: fraction conversion is exactly `(numerator as f64) / (denominator as f64)`, including values above `2^53`; each component performs a separate `weight * f64::from(component)` followed by one sequential `+=` in canonical relation/component order. No exact-rational intermediate, fused reduction, parallel reassociation, or `f32` accumulation is equivalent. Region finalization first checks graph/source/link/expected bindings, then enforces explicit maxima for sparse relations visited, present-relation component accumulations, retained candidate bytes, and peak working bytes. Only its nonserializable candidate can enter full Arrow/Parquet region-table validation and mint the runtime receipt.

Zero-overlap pairs are omitted under that exhaustive declared-zero rule. Typed membership, same-slide ancestry, unique pairs, exact fraction rules, dependencies, logical identity, assessment count, and retained budgets are validated. Every relation—including `fully_contained` and an ancestry-consistent region—remains a provenance-bound area declaration supplied by a reviewed producer because hierarchy carries no geometry. C-05 does not call that declaration independently geometrically verified. FND-02 must later validate it against canonical region/window geometry without changing C-05 link identity.

## Provenance and artifact graph

Version one supports direct patch extraction and derived region/slide tables only. Direct region or direct slide model output requires a later reviewed version because no honest support contract is presently available.

- `patch`: exact patch context, footprint, and overlap-graph artifact IDs/digests;
- `region_from_patches`: exact patch-support and patch-region-link artifact IDs/digests;
- `slide_from_patches`: exact patch-support and source patch-table artifact IDs/digests; or
- `slide_from_regions`: exact region-support and source region-table artifact IDs/digests.

These variants define lineage/support evidence, not a polygon, tissue mask, or full observation window. Region support remains producer-declared until FND-02 geometry verifies it; slide support is only the transitive sampled support of its lower-level inputs.

Derived-table finalization consumes verified lower-level receipts, recomputes every output row with the frozen algorithm/order under explicit decoded/retained budgets, and requires exact status, component bits, and logical digest agreement before issuing the derived receipt. Merely naming a derivation artifact never promotes arbitrary supplied region/slide bytes.

Slide finalization clarification accepted 2026-08-23 under DEC-0037: source rows are visited in canonical table order; every present component is promoted to `f64` and added sequentially into one `D`-component accumulator; the divisor is exactly `present_count as f64`; each component is divided once, cast once to `f32`, and signed-zero canonicalized. Non-present rows are excluded. No present source produces the singleton `missing_vector` row. Contributor work counts every lower-level row, component work counts only present rows times `D`, and peak working storage is `O(D)` plus the singleton output construction. The verified support capability retains a domain-separated fixed-size binding to the lower table's owning slide; graph minting requires it to equal both decoded provenance and expected-singleton ownership before finalization or resource checks. Both source variants reuse the existing slide Arrow/Parquet profile and can mint a receipt only from the unforgeable finalization candidate.

Absent roles are represented by different variants, never dummy IDs. Role-ordered dependency arrays reject duplicates where two roles cannot legitimately share content. Strict canonical JSON, bounded strings/counts/nesting, exact schema versions, and privacy-safe errors are mandatory.

Publication is acyclic and fixed:

1. publish expected sets, patch identity/context/footprints/overlap, source/execution records, then the `patch` support descriptor;
2. publish direct patch provenance, physical patch table, and its runtime-only verified table receipt;
3. independently publish cell assignments/edges and the exhaustive patch-region link from expected sets/context/footprints/producer evidence; links never depend on patch-vector bytes;
4. after patch support plus patch-region link exist, publish `region_from_patches` support, derived-region provenance, region table, and runtime receipt in that order;
5. after the selected lower-level table/support exist, publish the matching slide-support variant, derived-slide provenance, singleton slide table, and runtime receipt in that order; and
6. optionally construct runtime-only bundle receipts that pair compatible verified table/support/link artifacts without changing or serializing any constituent identity.

Separate verified receipts exist for each support, matrix, assignment, edge, and link artifact. Do not require one monolithic graph: a valid project may have only one level. Compact public table/link/bundle receipts are runtime-only unforgeable Rust values obtained after exact catalog/schema/dependency/table-manifest, physical content, logical digest, support, and provenance checks pass; they cannot serialize or enter a catalog. Recomputed `MultiscaleEmbeddingQcSummary` is returned by table readers/receipts and is not a persisted descriptor field.

The DHAT peak is at most 320 MiB and strictly below one forbidden 100,000-edge copied-vector payload; neither threshold may be relaxed from a calibration run.

## Stop and escalation conditions

1. Identity, row linkage, slide ancestry, frame, scale, stride, overlap, receptive field, observation support, or provenance would have to be inferred from paths, order, coordinates, length alone, or development metadata.
2. Arbitrary region overlap would be called geometrically verified without an FND-02 geometry artifact and oracle.
3. Any importer requires `.pt`, `.pth`, pickle, arbitrary Python-object deserialization, implicit casts/transposition, row dropping, ID synthesis, or unknown missingness.
4. A vector would be repeated into a cell/region link, result JSON, or one row per linked cell.
5. A table mixes slides, frames, scale contexts, models, dimensions, pooling contracts, or measured/predicted semantics.
6. Physical parsing cannot be bounded before stock decode or requires whole-file/multi-group retention.
7. Patient/sample/source identifiers, source values, credentials, or ambient remote paths would enter fixtures, errors, logs, ledgers, or commits.
8. Registry dependency/version/publication, global install, remote mutation, new worktree, result/config/CLI change, or unsafe code becomes necessary without an accepted decision and authority.
