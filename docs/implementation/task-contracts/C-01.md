## Objective

Create the stable in-memory identity and hierarchy substrate that states what each object is, its explicit parentage, and whether it is biological, technical, or structural. It must represent paired/repeated and multisite/multiregion/multicore designs without deriving identity or replication from filenames, row counts, or loose compatibility `case_id` strings.

## Proposed package boundary

- `marklab-core`: validated identity newtypes and the typed hierarchy-ID enum only. It depends on no Marklab package.
- `marklab-data`: immutable `CohortHierarchy`, nodes, parent rules, replication roles, explicit repeated-measure sets, validation errors, and design summary. It depends only on core.
- `marklab-project`: owns an optional installed immutable hierarchy so the project is the immediate stateful caller. It depends on data.
- root `marklab`: a direct dev dependency may exercise integration/benchmark behavior, but no compatibility-root re-export is added in C-01. Stable promotion waits for C-03 schema/digest work, result 0.4, real-data validation, and downstream typed randomization.

The descending layers become `marklab-core` → `marklab-data` → `marklab-project` → `marklab-workflow` → root `marklab`. Higher packages may skip a layer but no dependency points upward.

## Frozen semantics

- IDs: `PatientId`, `SiteId`, `SpecimenId`, `TimepointId`, `BlockId`, `SlideId`, `SectionId`, `CoreId`, `RegionId`, `CellId`, and `PatchId`; plus typed `HierarchyId`/`HierarchyKind`. Each value is unique within its typed kind and one analysis bundle; identical text in different kinds is legal. IDs are 1–255 UTF-8 bytes, satisfy `value.trim() == value`, and contain no `char::is_control`. No normalization, path handling, splitting, or parent inference occurs. A `TimepointId` is a globally unique object ID, not a reusable label such as `pre`.
- Parentage: every node has at most one compact containment/lineage parent. Supported child/parent kinds are enumerated; nested regions are allowed and the entire parent graph must be acyclic. A root slide is allowed as a multi-donor TMA container.
- Replication/source: each node is explicitly `BiologicalUnit`, `BiologicalSubsample { biological_source }`, `TechnicalReplicate { biological_source }`, or `Structural`. Roles are restricted by object kind: site/timepoint/cell/patch are structural only; patient is biological or structural; specimen permits all four roles; and block/slide/section/core/region permit subsample, technical, or structural roles but cannot be biological units. Source and containment are independent typed relations: a donor TMA core may be contained by a recipient slide while naming its patient/specimen biological unit. Each source must exist, be `BiologicalUnit`, and differ from the node, but need not be a containment ancestor. Nothing becomes independent from cell/patch count.
- Resolution: a node resolves most specifically to itself when biological, to its explicit source when a subsample/technical replicate, or to its nearest source-bearing/biological parent when structural. Its bounded biological lineage also retains any enclosing declared patient unit above a biological specimen, and a public membership query lets downstream callers select an explicit level without changing nearest-unit resolution. Every non-context terminal observation branch and every repeated-set member must resolve; an unrelated biological node elsewhere cannot make it valid. Multiple declared biological levels may coexist, and this infrastructure does not choose a downstream randomization unit.
- Pairing/repeated measures: an explicit set names one biological unit plus at least two distinct, same-kind observation nodes (`Specimen`, `Slide`, `Section`, `Core`, or `Region`) whose biological lineage contains it. Each observation belongs to at most one set globally, and each biological-unit/observation-kind pair owns at most one set; a patient may therefore own one specimen set and one core set but not two specimen sets. Declaration order is retained deterministically but has no temporal/condition meaning. Size two increments an explicit pair-set count; size greater than two increments a repeated-set count. Neither makes an automatic whole-cohort claim.
- Summary: exact counts by object kind/role; active sites reached by declared biological units; pair/repeated-set counts; and multicore/multiregion counts only when at least two peer cores or top-level (non-nested) regions belong to the same declared biological unit. A nearest specimen and its enclosing patient are each factual declared levels, so an object contributes at both levels; no level is silently selected. Empty site nodes and nested regions do not inflate design claims. One patient-to-site link means cohort/enrollment site only, not collection/scanning/assay site.
- Project integration: installing a hierarchy is one-time and non-overwriting in this in-memory phase.
- Deterministic error precedence: invalid ID construction; duplicate/conflicting node declaration; missing required/referenced parent; unsupported nesting; cycle; unsupported role-kind pair; biological-source/terminal resolution; repeated-set validation. Within linked repeated sets, missing/non-biological units and missing observations precede duplicate unit/kind sets, globally reused observations, and source-resolution mismatches.

## Required red tests

1. Every ID rejects blank, surrounding-whitespace, control-character, and over-limit values while preserving an opaque filename-like value exactly.
2. Hierarchy construction rejects duplicate IDs; a repeated declaration with a different parent returns `ConflictingParent` rather than silently replacing it.
3. Missing explicit parents/referenced parents and unsupported parent-kind pairs are typed errors.
4. A nested-region cycle is rejected deterministically before a hierarchy is returned.
5. Biological subsamples/technical replicates reject absent, self, or non-biological sources; each terminal observation branch must resolve even when an unrelated biological unit exists.
6. Explicit same-kind two-observation sets increment pair-set counts; larger sets increment repeated-set counts; active multisite, peer multiregion, and multicore summaries come only from explicit nodes/links/source resolution. Include a TMA fixture whose core parent is the recipient slide and whose biological source is the donor unit.
7. A filename-like cell or patch ID with no parent fails `MissingParent`; no path or delimiter inference API exists.
8. `MarklabProject` accepts one validated hierarchy, exposes it immutably, and rejects overwrite without changing existing state.
9. Unsupported role-kind pairs are rejected before source validation; cell, patch, site, timepoint, block, slide, section, core, and region objects cannot become biological units.
10. Nested patient/specimen biological levels preserve nearest resolution while patient-level repeated sets, explicit membership queries, and core/region summaries include the enclosing declared unit.
11. Missing/non-biological repeated units, missing/reused observations, duplicate unit/kind sets, empty sites, nested-region summaries, the exact ID limit, and 10,000-node chain/cycle-tail cases are covered directly.
