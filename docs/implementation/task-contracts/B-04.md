## Frozen contract

- Input: immutable borrowed `Pattern` and `AnalysisConfig`, represented in the project only by kind, SHA-256 digest, and byte length.
- Output: the existing `MarkedPatternResult` and canonical result-format 0.3 JSON; no field or projection changes.
- Cache key: tagged and length-prefixed node kind/version/specification, ordered input reference triples, configuration digest, explicit execution policy, scheduler inline-output limit, and implementation identity (`marklab` version, adapter revision, result 0.3, parallel feature state).
- Thread policy semantics: B-04 keys the declared configuration. `threads = "auto"` remains the literal requested policy rather than ambient host capacity; persistent host/backend execution provenance and invalidation belong to C-03/WS-13. The parity acceptance fixture uses an explicit one-thread policy.
- Cache miss: the executed value is encoded, decoded for schema validation, and canonically re-encoded. The exact candidate bytes are decoded and re-encoded once more; a non-fixed-point codec is rejected before commit so the returned value and committed artifact have one stable representation.
- Cache hit: verified bounded inline result bytes are decoded through `ResultDocument`; corruption/codec failure is an error, never a silent miss.
- Failure: graph/input verification, execution, encoding, decoding, canonical-stability, size, or commit failure records no success and no cached output.
- Persistence boundary: in-memory project state only in B-04. C-03/WS-11 owns durable schema, recovery, path/object storage, and large artifacts.
- Scientific claim ceiling: infrastructure and exact compatibility only; no new estimator or interpretation.
- Resource-bound ceiling: scheduler/project limits bound retained bytes per inline artifact. B-04 codecs materialize output before the scheduler can measure it, and fixed-point validation may hold two bounded encodings transiently, so this is not a peak-memory bound. Streaming/bounded artifact writers belong to C-03.
