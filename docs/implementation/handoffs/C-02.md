## API, schema, and semantic boundaries

- New public APIs exist only in `marklab-core` and `marklab-data`. Root `marklab` has no new stable re-export or adapter.
- A matrix always maps source values to target values. Rows follow target axes for frame transforms; serial rows are semantic volume X then Y. No equal-unit/equal-axis identity is inferred.
- Missing pixel calibration is absence of a transform, never identity or `1.0 micrometer/pixel`.
- `None` uncertainty means no scalar bound is available, distinct from a known zero radius. C-02 never composes or propagates uncertainty.
- Missing serial sections retain ordinal/Z/thickness metadata but have no placement. Distorted sections require target-volume uncertainty. Neither state implies cell correspondence or interpolation.
- The current result 0.3 `registration_error_um` and current `Transform2D` remain compatibility records; C-02 does not reinterpret them.
- Persistence, artifact digests, migrations, versioned interchange, and result 0.4 references remain C-03 ownership.

## Assumptions

1. Typed frame/transform/uncertainty IDs identify declarations within one validated analysis bundle; their text carries no unit, axis, source, target, or path semantics.
2. Pixel coordinates are continuous frame coordinates and may be negative; raster bounds belong to an image/storage adapter.
3. Serial sections are parallel to the target volume's semantic X/Y plane. Oblique geometry requires a later reviewed model.
4. A caller explicitly selects transform chains and inferential boundaries; registry membership does not authorize automatic path choice or scientific analysis.
