## API, schema, and semantic boundaries

- `ArtifactRef` still identifies exact encoded bytes. `ArtifactId` additionally binds schema version, exact table declaration, dependencies, and bounded semantic metadata. Store location never changes scientific identity.
- A valid `TableManifest` is a declaration, not proof that arbitrary bytes physically match Arrow or Parquet. Physical conformance belongs to C-04/WS-25.
- Catalog JSON is strict format `marklab.artifact_catalog` version 1 with a canonical fixed point and no invented migration from a nonexistent predecessor.
- Managed keys derive only from `ArtifactId`; external locators are reference-only and cannot enter reserved managed/staging/quarantine/lock namespaces.
- Verification failures are integrity errors. They never become ordinary cache misses and never authorize node execution.
- The local store protects cooperative API users within a trusted operator-controlled root. Its file locks are advisory against code that bypasses the API, and it does not claim to sandbox hostile Rust code or hostile root administration.
- Root result 0.3, config 0.2, `OutputWriter`, current CSV/Parquet adapters, CLI commands, and scientific implementations remain unchanged.

## Assumptions

1. Store roots are provisioned and administered by a trusted operator; callers do not mutate managed namespaces behind the capability API.
2. One `StoreId` is bound consistently by runtime configuration. A catalog locator is portable metadata, not a credential or endpoint.
3. Hard-link publication and writable directory handles are supported by a target before that target is admitted to the durable-store support envelope.
4. Artifact producers know the exact expected byte digest and length before managed publication; unknown-length streaming is a separate future contract.

## Independent review and structural judgment

The contract reviewer identified nine ownership, integrity, ordering, privacy, and compatibility gaps before freeze; all were incorporated. The implementation reviewer then found six material gaps: staging cleanup ownership, active-publisher/recovery coordination, partial quarantine reporting, the reserved lock-file namespace alias, fixed golden vectors, and same-length mutation coverage. Its closure-document audit found a seventh implementation issue: query-bearing keys contradicted the locator privacy contract. A behavior-focused regression failed before that boundary was fixed. Final re-review found no other material correctness, security-boundary, complexity, placement, or scope issue.

The three large implementation files remain separated by real responsibilities: `artifact.rs` owns validated identity/schema/location values, `catalog.rs` owns strict wire and dependency-graph semantics, and `store.rs` owns one capability/publication/recovery lifecycle. They were not split merely for line count. Physical format adapters, project snapshots, and remote stores must be separate owners rather than extending these modules into catch-all infrastructure.
